# Cortana v1.4.1：确定斩杀与残局必胜

本版修复“明明能斩杀，却随机不用技能或选到小牌”的问题。游戏规则不变；算法、证明结果和概率不展示在游戏页面。

- 最新决策：[`dist/ai.js`](../dist/ai.js)
- 真实结算：[`dist/game.js`](../dist/game.js)
- 新回归：[`tests/cortana-v1.4.1.test.cjs`](../tests/cortana-v1.4.1.test.cjs)
- v1.4 存档：[`dist/cortana-v1.4/`](../dist/cortana-v1.4/)

## 决策顺序

1. 找到本回合保证扣血归零的动作，必定从中选择。
2. 若没有立即斩杀，检查本回合保证终局获胜（包括牌尽血量领先）。
3. 检查多回合强制斩杀，优先最短的已证明回合数。
4. 检查多回合强制获胜。
5. 没有证明时，继续 v1.4 的公开信息玩家模型与概率策略。

每个候选都是“牌值＋是否使用技能”的联合动作。必须对玩家的每一种合法出牌及交换都成立，才算证明。不会把最可能的玩家应对、正的启发式评分或搜索到一条顺利路线当成必胜。

相同证明深度下，如果普通出牌已经足够，则选普通动作。需要双倍才能立即斩杀时，技能发动概率严格为 1。无关牌的概率严格为 0；只在已证明安全的候选之间按实际张数分配概率。

## 20 类本回合斩杀

前提：玩家已经交换，或者剩余牌全为 1、无法合法交换。

| 玩家最大牌 | C 可用的斩杀牌 |
| --- | --- |
| 1 | 1.5、2、2.5、3 |
| 1.5 | 2、2.5、3 |
| 2 | 2.5、3 |
| 2.5 | 3 |

这 10 种点数组合分别覆盖玩家 1 血时的普通攻击，以及玩家 2 血时的双倍攻击，共 20 类。C 自身残血不会改变保证斩杀的优先级。交换带来的重复牌按真实公开记录计算，不受原始单方牌数限制。

玩家仍有同点牌时可打平；仍可合法交换时可免伤；3 血不能被一次双倍扣光。技能用尽后不能虚构双倍攻击。牌尽血量领先与斩杀分别标记为 `win` 和 `lethal`。

## 连续斩杀的可达回归

表中 HP 为剩余血量，交换指玩家技能。所有路线均验证每一种合法玩家应对，而不只验证列出的一条路径。

| 场景 | C 手牌／HP | 玩家手牌／HP | 技能状态 | 关键策略 |
| --- | --- | --- | --- | --- |
| 满血两次攻击 | 1,2,2,2／1 | 1,1,1,1.5／3 | C 可用，交换已用 | 普通 2 再双倍 2；最迟两回合 |
| 普通连续攻击 | 2,2.5,3／1 | 1,1,1／2 | 双方已用 | 两次普通获胜 |
| 逼掉平局牌 | 2,2,2／1 | 1,1,2／2 | C 可用，交换已用 | 普通 2；平局后双倍，命中后普通；最迟三回合 |
| 逼掉 3 或承受一击 | 2,2.5,3／2 | 1,1.5,3／2 | C 可用，交换已用 | 普通 3；根据公开结果完成后续斩杀 |
| 保留最大牌应对交换 | 1,1,2.5,3／1 | 1,1,2,2／1 | 双方可用 | 普通 2.5；被交换后用 3 |
| 没有最大牌也能必杀 | 1,1,1.5,2／2 | 1,1,1,2.5／1 | 双方可用 | 普通 1.5；三类应对后都可结束，避免开双倍自杀 |
| 换回的小牌完成最后一击 | 1,1,2,2／1 | 1,1,1,1.5／1 | 双方可用 | 2 被交换后，再用 2 逼平，最后用 1.5 |
| 用户报告的七张牌局面 | 1,1,1,2,2,2.5,3／3 | 1,1,1,1.5,1.5,2,2／2 | C 可用，交换已用 | 必定双倍，且只选 2.5 或 3 |

各例的完整合法前史写在测试的 `fixtures141` 中。最后一例只需要两个回合：玩家 3 与 C 的 1.5 交换，再由玩家普通 2.5 对 C 的普通 3 到达。旧版在该局面选择立即斩杀动作的概率约 13.97%；本版为 100%。

## 搜索范围与信息边界

- 手牌超过四张时，证明搜索最多三回合。
- 剩余四张或更少时，搜索至终局：最多剩余牌数加一次尚未使用的交换。
- 普通回合使双方牌数各减一；交换不减牌数但消耗唯一技能，因此递归严格终止。
- 以牌值多重集合、双方血量、技能状态、剩余深度和证明目标缓存结果；不依赖玩家模型权重。
- 深度边界未证明时只代表未知，不是必胜或必败。大手牌下更远的强制路线仍可能未被识别。
- 当前决策与原概率模型的未来推演共用同一决策优先级。

C 继续只接收自己的手牌、公开血量、自己的技能状态、已亮牌历史和从公开行动学习的模型权重。不会读取玩家实际手牌对象、当前选牌、技能按钮、操作时间或鼠标状态。

回合开始锁定唯一计划并深冻结。概率支持集收窄后，用最终 C 分布生成学习证据；亮牌后才更新权重。实际手牌顺序被保留，零概率末项不会因为浮点累计误差被意外抽中。

## 验证

```sh
node tests/game.test.cjs
node tests/cortana.test.cjs
node tests/cortana-v1.3.test.cjs
node tests/cortana-v1.4.test.cjs
node tests/cortana-v1.4.1.test.cjs
node tests/ai-v1.4.1-benchmark.cjs 10000 250
```

新测试包括 20 类直接斩杀在不同自身血量及模型权重下的支持集检查、8 个真实可达局面及 158 条后续分支、9,000 个一至两张手牌的合成规则局势与独立求解器对照，以及四张手牌的长路线检查。合成局势用于穷举规则，不声称每个都能从初始牌组到达。

同时覆盖实际界面结算、极端随机票值、重复与乱序手牌、零概率采样、隐藏字段访问保护、锁牌不重抽、证据冻结、交换后的第九回合，以及 80 局固定种子的完整新版本游戏。历史版本运行各自存档的代码。

## 独立固定种子基准

每种模拟对手、每版 250 局，种子从 10000 开始。得分率为胜局加半个平局占比：

| 模拟玩家 | v1.4 | v1.4.1 |
| --- | ---: | ---: |
| 随机出牌，偶尔交换 | 77.0% | 78.2% |
| 保留交换反制 C 技能 | 56.2% | 57.2% |
| 从不交换 | 71.2% | 70.8% |
| 积极交换最小合法牌 | 61.2% | 62.4% |

这些是指定模拟的结果，不代表真人胜率；本次验收核心是确定斩杀不再被随机放弃，并不保证每类对手的小样本得分率都提高。
