# Cortana v1.3 决策说明

这份说明供开发与审阅使用。**游戏界面不展示这些运行算法、抽牌权重、概率参数或评分。** 页面只展示玩法规则、C 已选牌状态和已发动的技能。

实现：[`dist/ai.js`](../dist/ai.js)。回合锁定与结算：[`dist/game.js`](../dist/game.js)。

## 1. C 能使用哪些信息？

只使用 C 自己的剩余手牌、双方公开血量、C 自己是否已用技能，以及已经结算的公开记录。

玩家初始牌组是固定的。C 从 `[1,1,1,1.5,2,2,2.5,3]` 出发，逐条处理记录：

- 普通回合：移除玩家公开打出的那一张牌。
- 交换回合：移除玩家打出的牌，再加入 C 在该回合交换给玩家的牌。

因此，在本游戏的固定初始牌组和全公开结算规则下，可以推算剩余牌的数量与点数；这是记牌推导，**不读取游戏内部的玩家手牌数组**，也不知道玩家本回合准备出哪张。

AI 不接收玩家当前选择、当前是否开启移花接木、鼠标操作、等待时长或未公开数据。没有跨局画像或偷偷调整概率。

## 2. 先判定技能，再锁定出牌

每次进入选牌阶段：

1. 若 C 的技能尚未使用，独立抽一次随机数，小于 `0.25` 就发动技能。
2. 发动时使用第 3 节的技能出牌分布；未发动时使用第 4 节的普通出牌分布。
3. 根据分布抽定一张牌，将「是否发动技能、出哪张牌」作为不可变计划保存。
4. 然后显示「已选牌」；如果技能发动，还会显示「伤害 ×2」。

计划在玩家操作之前确定。换牌、取消技能或反复点击都不会重抽；确认出牌时直接使用已锁定的牌。上一版依据玩家是否使用移花接木切换出牌方案的逻辑已移除。

技能仍**每局最多一次**：平局、被移花接木抵消也消耗次数。没有预定发动回合，没有后期必定发动的补偿；每回合 25% 不表示每四回合必定发动。

## 3. 发动技能回合的出牌概率

| 类别 | 总概率 |
| --- | ---: |
| 当前最大点数的牌 | 1/3 |
| 当前最小点数的牌 | 1/4 |
| 其余卡牌 | 合计 5/12，每张均分 |

同点数的最大牌或最小牌作为一组，组内按具体卡牌均分。

边界情况：

- 只剩最大、最小两种点数时，按原权重归一化为 **4/7 和 3/7**。
- 所有牌同点数时，各张等概率。
- 只有一张牌时必选它。

初始牌组下，每张 1 点牌为 `1/12`，3 点牌为 `1/3`，1.5、两张 2、2.5 这四张牌各为 `5/48`。

**技能回合不叠加普通评分策略**，确保指定概率保持准确。

## 4. 普通回合怎样做概率判断？

### 4.1 估计胜负概率

C 暂时假设玩家剩余的每一张具体卡牌等概率被打出。这是一个简单的估计模型，不宣称知道玩家真实意图。

对 C 的每张候选牌 `c`，计算：

```text
W(c) = 玩家剩余牌中点数小于 c 的张数 / 玩家剩余总张数
L(c) = 玩家剩余牌中点数大于 c 的张数 / 玩家剩余总张数
```

相同点数算平局。重复牌逐张计数，例如开局玩家三张 1 点牌共占模型概率 `3/8`。

### 4.2 胜负评分与保留大牌

```text
A = 玩家剩 1 血时取 2，否则取 1
B = C 剩 1 血时取 2，否则取 1

R(c) = (c - C 最小牌) / (C 最大牌 - C 最小牌)
F = (C 剩余牌数 - 1) / 7

S(c) = A × W(c) - B × L(c) - 0.3 × R(c) × F
```

若 C 所有牌相同，`R(c) = 0`。

含义：

- 玩家只有 1 血时，更重视能赢下本回合的牌。
- C 只有 1 血时，更重视避免输掉本回合。
- 大牌有保留成本，避免在小牌也足以获胜时浪费大牌。
- 剩余牌越少，保留成本越低；最后一张牌不再需要保留。

这是启发式评分，没有读取玩家当前出牌，也没有穷举一个玩家未公开的选择。

### 4.3 从评分转换为随机出牌

先将评分转换为 softmax 概率：

```text
Q(c) = exp(S(c) / 0.45) / 所有 C 手牌的 exp(S / 0.45) 之和
```

实现中会先从所有评分减去最高分，保持数值稳定，不改变概率。

最终概率：

```text
P(c) = 0.20 / C 剩余牌数 + 0.80 × Q(c)
```

即 **20% 均匀随机 + 80% 按评分抽牌**。它不是「80% 必选最高分牌」，评分较低的牌也一直有机会出现。

### 开局示例：双方满血、均未出牌、C 本回合不发动技能

| 点数 | 总出牌概率（约） |
| --- | ---: |
| 1（三张合计） | 13.54% |
| 1.5 | 7.68% |
| 2（两张合计） | 25.17% |
| 2.5 | 22.14% |
| 3 | 31.48% |

这是开局状态的结果，**不是固定整局使用的概率**。公开牌组和血量改变后会重新计算；四舍五入可能导致显示总和不等于 100%。

## 5. 验证与可复现模拟

```sh
node tests/game.test.cjs
node tests/cortana.test.cjs
node tests/cortana-v1.3.test.cjs
node tests/ai-benchmark.cjs
```

验证覆盖：精确 25% 技能判定、最大/最小分组及缺牌、公开换牌记录推导、隐藏字段访问保护、禁止玩家操作触发重抽、状态框、双倍伤害、抵消、次数限制、第 9 回合与 500 局固定种子对局。旧版测试分别运行在保留的旧版入口代码上。

模拟使用同样的 25% 技能规则，仅替换普通回合出牌算法。每组 6,000 局，种子和对手规则固定：

| 模拟对手 | C 普通出牌策略 | 胜 / 平 / 负 | 得分率（胜记 1、平记 0.5） |
| --- | --- | --- | ---: |
| 均匀出牌，随机使用换牌 | 均匀随机基线 | 3207 / 159 / 2634 | 54.77% |
| 均匀出牌，随机使用换牌 | v1.3 公开信息评分 | 3903 / 170 / 1927 | 66.47% |
| 均匀出牌，保留换牌抵消技能 | 均匀随机基线 | 2568 / 196 / 3236 | 44.43% |
| 均匀出牌，保留换牌抵消技能 | v1.3 公开信息评分 | 3864 / 213 / 1923 | 66.17% |

这些结果说明新策略在指定模拟条件下更强，不能视为真人胜率，也不保证对所有玩家策略都更强。后续可根据实际游玩反馈调整保留成本、温度或随机比例。
