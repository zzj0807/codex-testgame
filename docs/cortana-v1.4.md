# Cortana v1.4：隐藏换牌预测与局势决策

本文件解释内部运行逻辑，**这些概率、模型和评分不展示在游戏页面**。页面仅展示规则、选牌状态和已经发动的技能。

- 决策模块：[`dist/ai.js`](../dist/ai.js)
- 游戏规则与结算：[`dist/game.js`](../dist/game.js)
- 测试：[`tests/cortana-v1.4.test.cjs`](../tests/cortana-v1.4.test.cjs)

## 1. 本版新增规则

玩家打出 **1 点牌时不能同时使用移花接木**。先选 1 点时技能按钮禁用；先开启技能再改选 1 点时，技能自动取消，次数不消耗。改选大于 1 点的牌后可以重新开启，但不会自动帮玩家开启。

结算层也会拒绝非法的「1 点 + 移花接木」组合。预测与模拟器完全遵守同一限制。

## 2. C 的信息边界

C 只接收：自己的手牌、双方公开血量、C 自己是否已用技能、已结算的公开出牌记录，以及只由这些公开行动更新的模型权重。

玩家剩余牌从固定初始牌组推算：普通出牌后移除玩家的牌；交换后移除玩家打出的牌，再加入 C 交换给玩家的牌。

C **不接收**玩家的真实手牌对象、当前选牌、当前技能开关、鼠标操作或操作时长。玩家是否已经用过移花接木，由公开历史中是否发生过交换推断，而非读取本回合按钮状态。

回合开始时完成分析，再抽定是否发动 C 技能和**唯一一张牌**，整个计划深冻结。C 不保存供玩家实际操作选择的两套出牌，不在玩家确认时重抽。移花接木与否只影响结算，不改变 C 已经锁定的牌。

## 3. 同时预测玩家是否交换、交换时出什么

对公开推算出的每种牌值，建立普通出牌行动；若技能未用，另外建立大于 1 点的合法交换行动。相同点数合并计算，但使用实际张数作为先验。

预测的是联合行动，例如「普通出 2」和「交换出 2」，并非分别随意猜一个技能概率和一个牌面。

以下情况直接不建立交换行动，因此猜测交换的概率 `q` 严格为 0：

- 玩家已经公开使用过移花接木。
- 玩家剩余手牌全是 1 点。

否则，所有交换行动的预测概率之和就是 `q`。不同 C 技能模式分别计算玩家反应，因为玩家能看到 C 是否发动技能，但看不到 C 的牌。

## 4. 三种玩家模型

每局初始模型权重均为 1/3，不跨局保留画像。

| 模型 | 组间先验：交换 / 普通 | 如何调整行动概率 |
| --- | --- | --- |
| 随机型 | 0.15 / 0.85 | 组内按实际牌张数分配 |
| 保命型 | 0.25 / 0.75 | 根据玩家预计收益与本回合直接死亡风险评分，温度 0.35 |
| 资源 / 反制型 | 普通模式 0.08 / 0.92；已公开双倍模式 0.55 / 0.45 | 倾向保留交换应对公开威胁，结合预计收益调整；交换条件下送最小合法牌，温度 0.45 |

资源型在决定交换时，把交换先验集中到最小合法点数：这会保留自己的更强牌，且不给 C 更强的牌。随机型和保命型仍覆盖其他合法交换行动，因此不假定所有玩家都这样做。

这是各模型的**先验**，不是最终固定交换概率。普通组和交换组各自归一化，避免交换可选牌的数量自动支配 `q`。

保命型评分为 `-C预计收益 - 0.4×玩家本回合死亡概率`。节省资源型以 `-C预计收益` 为基础，交换消耗偏置最多 0.06，普通大牌消耗偏置最多 0.04，并随剩余牌减少而减弱。

按 `先验 × exp(评分 / 温度)` 归一化得到每种模型的联合行动分布，再按模型权重混合。**对所有 C 候选牌使用同一份玩家行动预测**；不会逐张假定玩家知道 C 正在评估的隐藏牌。

## 5. 两回合局势前瞻

对 C 的每张候选牌和玩家的每个合法行动，按真实游戏规则模拟：

- 普通回合落败方扣 1 血。
- C 发动技能时落败方扣 2 血，双方都可能被直接击败。
- 遭遇移花接木时不扣血，卡牌交换回手。
- 平局或被交换抵消也消耗 C 的技能。
- 玩家交换后消耗唯一一次技能。

当前回合后再推演一回合；前瞻期间固定当前模型权重，不假设已经知道未来行动。重复牌值合并，后继局势缓存，限制计算量。

真实终局使用 `C获胜=+1、平局=0、C落败=-1`。非终局边界采用：

```text
V = tanh(0.65×血量差 + 0.7×牌组对比 + 0.12×保留C技能价值 − 0.14×保留玩家交换价值)
```

牌组对比是所有剩余牌两两比较的平均胜负符号。C 技能保留价值结合最强牌的获胜比例、玩家是否 2 血及 C 是否 2 血，始终非负。玩家交换价值只在未用技能且存在大于 1 点的牌时计入。

这是有限前瞻的启发式收益，不是数学上保证最优的解，也不是经过真人数据校准的胜率。

## 6. C 的出牌分布与发动概率

同一技能模式下，C 的每张牌按所有玩家联合行动的概率计算收益：

```text
U(牌) = 所有「玩家牌值、是否交换」行动的 概率 × 模拟后继收益 之和
```

因此，既考虑出大牌斩杀，也考虑大牌可能被交换走；并不因为猜测 `q` 高就直接认定玩家会交换。

C 的分布与玩家反应迭代 4 轮，每轮：

1. 在当前 C 出牌分布下预测玩家行动。
2. 用预测分布计算 C 每张牌的收益。
3. 以温度 0.22 转换评分概率，更新目标中加入 20% 均匀随机。
4. 当前分布只向新目标移动一半，降低来回跳变。

从均匀分布开始经过四轮阻尼，最终显式均匀随机基底为 25%，其余为各轮评分分布的混合。不会始终出一张确定的大牌或小牌。

技能未用时，分别评估普通模式 `U0` 和双倍模式 `U2`：

```text
发动概率 = sigmoid(log(1/3) + 6×(U2 − U0))
```

收益相同时为 25%，有利时提高，不利时降低。技能用过后为 0。取消旧版固定 25% 的逐回合判定及固定最大/最小牌分布。

玩家 2 血时，直接斩杀会进入终局收益；C 自己 2 血时，被反杀也进入终局负收益。玩家 1 血时，普通伤害已可结束游戏，因此不会机械地把技能伤害翻倍当成额外收益。

## 7. 只在亮牌后学习

锁牌时保存三种模型对玩家联合行动的预测证据。双方亮牌后，只查阅这份**事先保存**的预测，使用玩家公开的牌值及是否交换更新权重：

```text
后验 ∝ 原权重 × 行动似然^0.35
新权重 = 0.1 + 0.7×归一化后验
```

每种模型至少保留 10% 权重，防止少量行动导致过度确信。更新时不读取实际 C 亮出的牌来重算预测，也不影响本回合已经锁定的出牌。新局恢复均匀权重。

## 8. 验证

```sh
node tests/game.test.cjs
node tests/cortana.test.cjs
node tests/cortana-v1.3.test.cjs
node tests/cortana-v1.4.test.cjs
node tests/ai-v1.4-benchmark.cjs
```

测试覆盖：1 点技能按钮禁用、自动取消不消耗、非法组合被结算层拒绝、模型合法行动、技能已用/只剩 1 点时 q=0、隐藏字段访问保护、不重抽、证据冻结、公开行动更新、两血斩杀与反杀、技能抵消、模拟器与实际结算逐步一致、最后一张牌交换后第 9 回合、80 局固定种子完整对局。旧版继续使用各自的存档代码运行回归测试。

独立审阅还检查了 234 个小手牌局势的归一化与交换合法性。初始满手牌决策在当前开发环境约 3～15 毫秒；设备性能不同会影响耗时。

平衡性脚本在双方都遵守「1 点不可交换」的规则下，对比 1.3 与 1.4，使用固定种子和四种模拟对手。结果只代表这些模拟，不代表真人胜率。

采用未用于调整策略的种子区间，从 10000 开始，各 250 局，C 的得分率为「胜局 + 0.5×平局」占比：

| 模拟玩家 | 1.3 | 1.4 |
| --- | ---: | ---: |
| 随机出牌，偶尔交换 | 75.0% | 77.0% |
| 保留交换，专门反制 C 技能 | 65.8% | 56.2% |
| 从不交换 | 72.0% | 71.2% |
| 积极交换最小合法牌 | 52.2% | 61.2% |

复现命令：`node tests/ai-v1.4-benchmark.cjs 10000 250`。

1.4 达到了依据公开局势预测和调整的设计目标，但不保证所有对手上的胜率都提高。专门保留交换来反制技能的玩家仍是明显弱点；后续可以扩大模拟玩家集合、增加搜索深度，再用独立样本比较策略。当前参数不是经过证明的最优解。
